# Componentes PO-UI — Fase 1 (protocolo, laço de eventos, componentes base) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Programas AdvPL rodando em `advplc serve` montam telas PO-UI como objetos
(`PoApp`, `PoPage`, `PoButton`, `PoInput`, `PoTable`, `PoTag`), tratam eventos em
codeblocks dentro de um laço não bloqueante e atualizam a tela ao vivo, inclusive por
timer.

**Architecture:** As classes nativas em Go (`pkg/vm/poui*.go`) mantêm uma árvore de
componentes por VM. `PoApp:Activate()` envia um `mount` ao navegador e entra num laço
que lê eventos de uma interface opcional `ComponentUI`, implementada pelo `Provider` do
`pkg/webui` sobre o SSE existente (evento novo `ui`) e uma rota nova `POST /ui`. Cada
handler roda via `callBlockSync` na VM da sessão. Os `Set` feitos durante um handler
saem num único `batch`. No frontend, um componente recursivo mapeia cada `type` para o
componente PO-UI correspondente.

**Tech Stack:** Go 1.27 (sem CGO), Angular + `@po-ui/ng-components` 21.23 (já
instalado), SSE/HTTP.

**Spec:** `docs/superpowers/specs/2026-11-20-poui-componentes-design.md` (fase 1 da
seção 8). As fases 2 a 4 terão planos próprios.

## Global Constraints

- O AdvPP segue **100% compatível**: `MsgInfo`/`MsgYesNo`/`FWMenuSelect`/`FWGetText`/
  `MSDIALOG`/`FWMBrowse` em `advplc serve` sem mudança, e todos os testes atuais passam.
- **Executáveis para macOS, Linux e Windows:** em toda task, `go test ./...` verde e
  `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build ./cmd/advplc` e
  `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./cmd/advplc` compilando. Gerar os
  binários **fora** da raiz do repositório (`-o "$(mktemp -d)/x"`); nunca sobrescrever
  `./advplc` nem `./advplc.exe`.
- Bytecode determinístico: nada desta fase altera o compilador.
- Go sem CGO. Nenhuma dependência nova nesta fase.
- Classes nativas, sem `#include`. Prefixo `Po*`.
- Somente modo web: fora de `advplc serve`, `PoApp:Activate()` falha com
  `PoApp: requer o modo web (advplc serve)`.
- Goroutines auxiliares (timers) **só postam** eventos e nunca tocam a VM.
- `POST /ui`: mesma checagem de origem e limite de corpo de `/reply` (8 MB).
- Frontend genérico: nenhum código específico de aplicativo. `make web` regenera
  `pkg/webui/dist`, que é versionado.
- Textos, comentários e commits em português. Commits sem linhas de atribuição a
  ferramenta ou modelo.

## Review Focus

1. Erro de runtime dentro de um handler: a tela continua viva, o erro aparece no console
   da página (evento `output`) e o laço segue. Teste em Task 3 (`TestHandlerErroNaoDerrubaLaco`).
2. Evento para id inexistente, ou sem handler: é ignorado sem pânico. Teste em Task 3
   (`TestEventoDesconhecidoIgnorado`).
3. `POST /ui` malformado (JSON inválido, id ausente, corpo > 8 MB, sessão inexistente):
   400/413/404 sem afetar a sessão. Teste em Task 1 (`TestUIPostInvalido`).
4. Navegador fecha com timer ativo: o timer para, `UIPost` não bloqueia depois do fim da
   sessão e não sobra goroutine. Teste em Task 3 (`TestTimerParaAoFecharSessao`).
5. `change` com valor não-string (número JSON): chega ao AdvPL como texto. Teste em
   Task 3 (`TestChangeValorNumerico`).

## Protocolo (fixado para todas as tasks)

Servidor → navegador: evento SSE `{"type":"ui","data":<op>}`.

```json
{"op":"mount","title":"Rede","tree":{"id":1,"type":"page","props":{"title":"Wi-Fi","actions":[{"label":"Atualizar","index":0}]},"children":[ ... ]}}
{"op":"batch","ops":[{"op":"patch","id":3,"props":{"value":"87%"}}]}
{"op":"close"}
```

Navegador → servidor: `POST /ui?s=<sid>` com `{"id":3,"event":"change","value":"abc"}`.

| type | props | eventos (value) |
|---|---|---|
| `page` | `title`, `actions:[{label,index}]` | `action` (índice 0-based) |
| `button` | `label`, `disabled`, `visible` | `click` (null) |
| `input` | `label`, `value`, `disabled`, `visible` | `change` (texto) |
| `table` | `columns:[{property,label,type}]`, `items:[{<property>:valor}]`, `visible` | `select` (índice 0-based da linha) |
| `tag` | `value`, `type` (`success`/`warning`/`danger`/`info`/`neutral`), `visible` | — |

O evento interno de timer chega pelo mesmo canal como `id=<id do timer>`, `event="timer"`.
O `mount` só leva o `PoPage` corrente: na fase 1, `PoApp` tem uma página.

- Produces (métodos do `*Provider`, que satisfazem `vm.ComponentUI` da Task 2):
  - `func (p *Provider) UISend(op []byte)`: enfileira `event{Type:"ui", Data: op}` via `s.send`.
  - `func (p *Provider) UIPost(id int, event string, value []byte)`: posta no `s.ui` sem bloquear (select com `s.quit` e `default` que descarta se o buffer de 256 estiver cheio).

  - `type poComp struct { id int; typ string; props map[string]any; children []*poComp; handlers map[string]advplrt.Value; obj *advplrt.ObjectValue }`

### Task 3: Laço de eventos, handlers, lote de patches e timers

**Files:**
- Modify: `pkg/vm/poui_native.go` (`ACTIVATE`, `CLOSE`, `SETTIMER`, `KILLTIMER`)
- Create: `pkg/vm/poui_loop.go`
- Test: `pkg/vm/poui_loop_test.go` (com um `fakeUI` que implementa `UIProvider` + `ComponentUI`: `sent [][]byte`, `in chan`, e `UINext` chamando `runtime.Goexit()` quando `in` é fechado)

**Interfaces:**
- Consumes: `ComponentUI`, `poAppState`, `setProp`, `mountJSON` (Task 2); `callBlockSync` (existente, `pkg/vm/vm.go:2205`).
- Produces:
  - `PoApp:Activate()`: envia `mountJSON`; `active=true`; laço `id, ev, val := ui.UINext()`, despacho e então, se `len(batch)>0`, `UISend({"op":"batch","ops":batch})` e zera o batch; sai quando `closed`, enviando `{"op":"close"}`, parando os timers e com `active=false`. Retorna `Nil`.
  - `PoApp:Close()`: marca `closed=true` (efetivo ao fim do handler corrente).
  - `PoApp:SetTimer(nMs, bBloco) -> nId`: `nMs < 100` → erro `PoApp:SetTimer: intervalo mínimo 100 ms`. Uma goroutine com `time.Ticker` chama `ui.UIPost(nId, "timer", nil)` até o canal de parada fechar. O handler é chamado como `Eval(bBloco, oApp)`.
  - `PoApp:KillTimer(nId)`: fecha o canal de parada (idempotente).
  - Despacho: `click` → `Eval(b, oComp)`; `change` → atualiza `props["value"]` sem gerar patch (o valor veio do navegador) e chama `Eval(b, oComp, cTexto)`; `select` → `Eval(b, oComp, aLinha)` (linha na ordem das colunas; índice fora da faixa → ignorado); `action` → `Eval(bAcao[índice], oComp)`.
  - Erro no handler: escrever `PoApp: erro no evento <event> do componente <id>: <msg>` na saída de console da VM (o mesmo writer de `ConOut`) e continuar o laço.
