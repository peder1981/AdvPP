# Componentes PO-UI — Fase 3 (vários programas por servidor) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um único `advplc serve --apps <dir> [--home <nome>]` atende vários programas AdvPL: cada `<dir>/<nome>.prw|.tlpp` vira a rota `/app/<nome>`, e cada janela é uma sessão com VM própria. Um app abre outro com `PoApp:Open(cApp)`.

**Architecture:** O `pkg/webui` ganha `NewApps(AppResolver)`: a sessão é criada com o `RunFunc` do app pedido em `/events?s=..&app=<nome>`, e `GET /app/{nome}` serve o `index.html` da SPA. Em `cmd/advplc`, um catálogo compila sob demanda com cache por data de modificação. O frontend lê o app da URL e trata a op `open`.

**Tech Stack:** Go 1.27 (sem CGO), Angular 21 + PO-UI 21.23.

**Spec:** `docs/superpowers/specs/2026-11-20-poui-componentes-design.md`, seção 6.5 e `PoApp:Open` (6.2). Base: branch da fase 2 (`feat/poui-componentes-fase2`, PR #17).

## Global Constraints

- AdvPP 100% compatível: `advplc serve programa.prw` (com `--watch` e `--debug-port`) segue idêntico; todo teste existente passa.
- Em toda task: `go test ./...` verde; executáveis `linux/amd64`, `linux/arm64`, `windows/amd64` e `darwin/arm64` com `CGO_ENABLED=0`, gerados **fora** do repositório; `TestBytecodeDeterminism` verde; `tests/poui/ao-vivo.sh` OK.
- Nome de app: `^[A-Za-z0-9_-]{1,64}$`. Qualquer outro → 400, para nunca virar caminho de arquivo (path traversal).
- Mesma checagem de origem e limites atuais (`sameOrigin`, 64 sessões).
- Erro de compilação de um app aparece na janela desse app (evento `error`); o servidor e os outros apps seguem.
- Frontend: `make web`. Commits em português, sem atribuição.

## Review Focus

1. `app=../../etc/passwd`, `app=a/b` ou `app=` com 65 caracteres → 400, sem tocar no disco. Teste em Task 1 (`TestAppsNomeInvalido`).
2. App com erro de compilação → a janela recebe `error` com a mensagem; outro app válido continua funcionando. Teste em Task 2 (`TestCatalogoErroDeCompilacao`).
3. Fonte alterado com o servidor rodando → a próxima sessão usa o código novo, sem reiniciar. Teste em Task 2 (`TestCatalogoRecompilaPorMtime`).
4. Duas janelas do mesmo app → duas VMs independentes, sem estado compartilhado. Teste em Task 2 (`TestCatalogoSessoesIndependentes`).
5. `PoApp:Open` com nome inválido → erro no AdvPL, e nada é enviado ao navegador. Teste em Task 3 (`TestPoOpenNomeInvalido`).

### Task 2: `advplc serve --apps <dir> [--home <nome>]` com catálogo

**Files:** Create `cmd/advplc/apps.go` (catálogo); Modify `cmd/advplc/main.go` (`case "serve"`: com `--apps`, o arquivo-fonte posicional não é exigido; `Options.apps` e `Options.home`; ajuda); Test `cmd/advplc/apps_test.go`.

**Interfaces:**
- Consumes: `webui.NewApps`, `webui.AppResolver`, `webui.ErrAppNaoEncontrado`, `webui.NomeDeAppValido` (Task 1).
- Produces:
  - `type catalogo struct { dir, home string; opts *Options; mu sync.Mutex; cache map[string]compilado }` e `type compilado struct { mtime time.Time; bc *compiler.Bytecode; err error }`
  - `func novoCatalogo(dir, home string, opts *Options) *catalogo`
  - `func (c *catalogo) fonte(app string) (string, error)`: procura `<app>.prw`, depois `<app>.tlpp`; `""` vira `home`; sem `home` e app `""` → `ErrAppNaoEncontrado`.
  - `func (c *catalogo) bytecode(app string) (*compiler.Bytecode, error)`: recompila quando a data de modificação muda; guarda também o erro de compilação, até o arquivo mudar.
  - `func (c *catalogo) resolver() webui.AppResolver`: cada sessão roda `vm.NewVM(bc)` com o banco (`attachDatabase`) e o console; erro de compilação → o `RunFunc` devolve `fmt.Errorf("erro de compilação em %s: %v", app, err)`, que o servidor mostra como evento `error`.
  - `func serveApps(opts *Options) error`: define `ADVPP_APPS_DIR` (caminho absoluto) no ambiente do processo e chama `vm.DefinirIconesValidos(webui.Icones())`.
  - CLI: `advplc serve --apps <dir> [--home <nome>] [--port n]`. `--watch` e `--debug-port` não se aplicam ao modo apps (a recompilação já é automática) e são ignorados com aviso em stderr.

- [ ] **Step 1: Testes que falham** (servidor via `httptest` sobre `webui.NewApps(..., c.resolver()).Handler()`, num diretório temporário):
  - `TestCatalogoRodaAppPeloNome`: `a.prw` faz `ConOut("sou a")`; `/events?app=a` recebe `sou a`.
  - `TestCatalogoHome`: com `--home a`, `/events` sem app recebe `sou a`.
  - `TestCatalogoTlpp`: `b.tlpp` é encontrado por `app=b`.
  - `TestCatalogoErroDeCompilacao`: `ruim.prw` com sintaxe inválida → evento `error` contendo `erro de compilação em ruim`; depois `app=a` ainda funciona.
  - `TestCatalogoRecompilaPorMtime`: troca o conteúdo de `a.prw` (data de modificação +1 s, via `os.Chtimes`) → a sessão seguinte recebe `sou a v2`.
  - `TestCatalogoSessoesIndependentes`: `cont.prw` usa um `Static` contador e faz `ConOut` dele; duas sessões imprimem `1` e `1`.
  - `TestServeAppsEnvDir`: `ADVPP_APPS_DIR` = caminho absoluto do diretório, depois de `serveAppsPrepara` (a parte de `serveApps` que não sobe o servidor).
  - `TestParseOptionsApps`: `parseOptions({"--apps","d","--home","x"})` → `apps=="d"`, `home=="x"`.
- [ ] **Step 2:** `go test ./cmd/advplc -run 'Catalogo|ServeApps|ParseOptionsApps' -v` → FAIL.
- [ ] **Step 3:** Implementar.
- [ ] **Step 4:** `go test ./cmd/advplc -v` → PASS.
