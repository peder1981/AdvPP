# Componentes PO-UI — Fase 4 (editor de código e terminal) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dois componentes próprios do AdvPP para desenvolvimento dentro da interface: `AdvCodeEditor` (CodeMirror 6, realce AdvPL/TLPP, marcação de erros, Ctrl+S) e `AdvTerminal` (xterm.js sobre um pseudo-terminal real), mais o suporte que faltava para marcar erros: `advplc check --format json` com linha e coluna.

**Architecture:** Os dois componentes entram no modelo `Po*` existente (tipos `editor` e `terminal`). O editor é só propriedades e eventos (`change`, `save`). O terminal abre um pty em Go (`creack/pty`, build tag `!windows`); a saída vai ao navegador em ops `term` (base64) enviadas pela goroutine de leitura; a entrada e o redimensionamento chegam como eventos `input`/`resize` pelo laço da VM. No Windows o componente devolve erro claro. Frontend: componentes Angular próprios com CodeMirror 6 e xterm.js.

**Tech Stack:** Go 1.27 (sem CGO) + `github.com/creack/pty`; Angular 21 + `codemirror`, `@codemirror/language`, `@codemirror/lang-json`, `@codemirror/legacy-modes`, `@codemirror/lint`, `@xterm/xterm`, `@xterm/addon-fit` (dependências aprovadas pelo operador em 2026-11-20).

**Spec:** `docs/superpowers/specs/2026-11-20-poui-componentes-design.md` (seção 6.2, `AdvCodeEditor`/`AdvTerminal`, e seção 10). Base: `feat/poui-componentes-fase3` (PR #18).

## Global Constraints

- AdvPP 100% compatível; executáveis para `linux/amd64`, `linux/arm64`, `windows/amd64` e `darwin/arm64` (`CGO_ENABLED=0`, gerados fora do repositório) em toda task; `go test ./...`, `TestBytecodeDeterminism` e `tests/poui/ao-vivo.sh` verdes.
- pty só com build tag `!windows`. No Windows, `AdvTerminal():New` devolve o erro `AdvTerminal: terminal indisponível no Windows nesta versão`. Os binários de teste de `pkg/vm` compilam para Windows e macOS.
- O terminal executa o programa pedido **sem shell implícito** (`exec.Command(prog, args...)`); é morto quando o laço termina.
- A saída do pty não bloqueia a VM; sessão encerrada → a goroutine de leitura termina.
- `check --format json`: só **acrescenta** campos (`line`, `col`, `message`); `file`/`ok`/`error` não mudam.
- Frontend: `make web` (com `node_modules` próprio no worktree). Commits em português, sem atribuição.

## Review Focus

1. Processo do terminal que termina sozinho (`exit`) → `OnExit(nCodigo)` chamado uma vez, e a tela não trava. Teste em Task 3 (`TestTerminalExit`).
2. Navegador fecha com o terminal aberto → processo morto, goroutine encerrada. Teste em Task 3 (`TestTerminalMortoAoFecharSessao`).
3. Saída binária ou UTF-8 cortada no meio de um caractere → chega íntegra (base64 de bytes crus). Teste em Task 3 (`TestTerminalBytesCrus`).
4. Texto grande no editor (1 MB) → `SetText`/`GetText` preservam o conteúdo byte a byte. Teste em Task 2 (`TestEditorTextoGrande`).
5. Erro de compilação sem linha/coluna reconhecível → JSON sem `line`/`col` (nunca 0 inventado). Teste em Task 1 (`TestCheckJSONSemPosicao`).

### Task 3: `AdvTerminal` (VM + pty)

**Files:** Create `pkg/vm/poui_term.go` (comum), `pkg/vm/poui_term_pty.go` (`//go:build !windows`), `pkg/vm/poui_term_windows.go`; Modify `go.mod`/`go.sum` (`github.com/creack/pty`), `pkg/vm/poui_native.go`, `pkg/vm/poui_loop.go`, `pkg/compiler/codegen.go`; Test `pkg/vm/poui_term_test.go` (`//go:build !windows`).

**Interfaces (Produces):**
- AdvPL: `AdvTerminal():New(oPai, cProg[, aArgs])` — tipo `terminal`, props `running` (bool), `height` (`"400px"`); `:OnExit({|o, nCodigo|})`; `:Write(cTexto)` (escreve no pty como se digitado); `:Kill()`.
- O processo começa no `Activate` (ou na hora, se a tela já estiver ativa), em pty 80×24.
- Eventos do navegador: `input` (value texto) → escrita no pty; `resize` (value `{"cols":N,"rows":N}`) → `pty.Setsize`.
- Saída: goroutine lê o pty (buffer 32 KB) e envia, **direto** por `UISend`, `{"op":"term","id":N,"data":"<base64>"}`; no fim do processo posta `exit` (código) com `UIPostWait(..., parar)` → `OnExit` + patch `running:false`.
- Fim do laço: mata os processos e fecha os pty.
- Windows: `New` devolve o erro da Global Constraint.

- [ ] **Step 1: Testes que falham** (Linux/macOS):
  - `TestTerminalEco`: `AdvTerminal():New(oPg, "cat")`; evento `input` `"oi\n"` → alguma op `term` cuja soma decodificada contém `oi`.
  - `TestTerminalExit`: `sh -c "exit 3"` → `OnExit` recebe 3 uma vez; patch `running:false`.
  - `TestTerminalBytesCrus`: `printf '\xc3'` seguido de `printf '\xa7'` → os bytes concatenados das ops = `c3 a7` (`ç`).
  - `TestTerminalMortoAoFecharSessao`: `sh -c 'echo $$; exec sleep 30'`, PID lido da saída; fecha `quit` → processo some em 2 s.
  - `TestTerminalResize`: evento `resize {"cols":100,"rows":30}` → `stty size` dentro do terminal responde `30 100`.
- [ ] **Step 2:** FAIL → **Step 3:** implementar (`go get github.com/creack/pty@latest`) → **Step 4:** PASS, `-race` limpo; binários de teste compilam para `windows/amd64` e `darwin/arm64`.
- [ ] **Step 5: Commit** — `feat(vm): AdvTerminal (pty real, entrada, resize, OnExit; Windows: erro claro)`
